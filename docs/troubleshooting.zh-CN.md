## 排错

- 找不到弹窗：先确认 Excel 的"信任对 VBA 工程对象模型的访问"已勾选。
- 确认工具在跑：任务管理器里应有 `pythonw.exe`；没有就重双击 `run.bat`。
- 依赖安装失败：在命令行运行 `python main.py`，可直接看到具体报错。
- "按 Tab 后列表框不消失"或"列表框被按 Tab 也关不掉"：
    
  双击 **`stop.bat`** 杀掉所有 VbeComplete 进程，再双击 `run.bat` 重启一次即可。
    
  这通常是因为之前残留了多个旧实例（已加单实例互斥体防复发）。
- **开着本工具时，PyCharm / VSCode 的项目窗口关不掉、卡住**：

  v27~v29 修过同一类问题（全局钩子不许在 VBE 之外常驻），v109 又修掉一个复发的点：
  读前台窗口标题用的 `GetWindowText` 是**跨线程同步调用**，IDE 退出拆窗口时它不理会
  消息，我们自己的主线程就被堵 1.5 秒以上，负责卸载钩子的循环因此停摆，钩子继续挂在
  人家退出流程上。现在读标题前有 200ms 封顶的"还响应吗"探针，且循环本身异常不死。
  先 `stop.bat` → `run.bat` 重启（改的是常驻进程，不重启不生效）再试。
  若仍复现，请带上日志：
  ```bat
  set VBECOMPLETE_LOG=1
  run.bat
  ```
  日志里 `reconcile: 本轮异常 …` 一行就说明循环曾差点停摆（v109 起它只是被记下，
  不会真的停）；`autopair: 钩子接管 …` / `poll: heartbeat …` 可看焦点与钩子状态。
- **关闭工作簿 / 退出 Excel 很卡，关完 Office 又被重新拉起**：
    
  通常用 `stop.bat` 结束进程后重启即可。若仍觉得慢，可用环境变量把工具调成最保守模式：
  ```bat
  set VBECOMPLETE_PROXY_TTL=0
  run.bat
  ```
  `=0` 表示彻底不缓存 COM 代理（每次用完即弃，最保守）。若怀疑宿主窗口探测误判
    
  （例如用 WPS 等非 Office 宿主），用 `set VBECOMPLETE_NO_WINDOW_GATE=1` 关掉窗口门。
- **两个列表还是同时出现（我们没让位）**：分两种情况看 ——
    
  ① 挡住的是 VBE 的**参数信息**（形参签名）：v65 起**有意不让位**（填实参时更需要
    
  候选），v66 起候选窗会自动**下移到签名窗下方**，两个窗不重叠。若候选窗**仍然压着**
    
  签名窗：v74 之前那是"变化检测漏了一次"（签名窗在候选窗不可见期间出现过又回原位），
    
  v74 已用"每轮实测复核"兜住。
    
  **若是"变量类型填的是自定义类模块"时压住参数信息（v80b）**，两个原因都在
    
  "时机"上，所以**不是每次都能复现**：
  - **提示窗句柄找得太早**：VBE 的参数信息窗是**用到才建**的（内建与自定义过程共用
      
    同一个 `PopupTipWndClass`），而旧代码只在"句柄缓存为空"时才去枚举它 ⇒ 头一次
      
    用自定义类模块触发参数信息时**永远找不到**这个窗 ⇒ 避让无从下手 ⇒ 我们的窗压住它。
      
    现在改成**按秒周期重扫**（`set VBECOMPLETE_VBE_POPUP_RESCAN=0.5` 可调更灵敏，
      
    默认 1s），窗一建出来下一次就认得出。
  - **让位标记记早了**：同一行有多个 `As` 槽位时（`Dim a As 类1, b As 类2`），旧代码按
      
    **整行**记"这里 VBE 不弹列表"，于是一个槽位的失败会**连累**另一个槽位不让位 ——
      
    该让位时不让，我们的窗就压住 VBE 的列表。现在按 **(模块, 行, 槽位列)** 记，
      
    并且标记**会过期**（`set VBECOMPLETE_YIELD_TTL=0.5` 调小，`=0` 干脆不记、每次都让位；
      
    默认 1.5s），兜住"VBE 只是慢了一拍"。
      
    ② 挡住的是 VBE 的**成员列表**：v76 起只要它的列表**真的可见**，我们在**任何**触发
      
    路径（轮询自动 / `Ctrl+Space` 手动 / 宽限补位）下都会收起来让位。**万一还撞车**，
      
    先把让位整个关掉复现（`set VBECOMPLETE_NO_YIELD=1`），再按下述顺序分三种原因：
      
    ① `VBE提示窗=()` 这类现象意味着压根没探到提示窗 —— 那是**类名 / 宿主 PID** 的问题
      
    （见第 ③ 条），先把提示窗类名加进探测清单；
      
    ② 手动 `Ctrl+Space` 的标记还挂着（v76 之后它已不再阻止让位，出现即异常）；
      
    ③ 两者几何明明相交却没被收掉 —— 窗口判据那一侧的问题。
      
    这三者的区分最终要靠窗口实测（`EnumWindows` + `GetClassName`）。
      
    ★v101 起 `log.py` 已恢复成**可开关的真实现**：启动前 `set VBECOMPLETE_LOG=1`，
      
    窗口探测量与按键接管都会记进 `VbeComplete.log`（心跳每3 秒一行），
      
    比手工枚举窗口快得多。
      
    ③ 这台机器的提示窗类名不在探测清单里（默认认 `NameListWndClass` /
      
    `PopupTipWndClass`）：枚举一下 Excel 进程的顶层窗口（`EnumWindows` + `GetClassName`）
      
    确认真实类名后，用 `set VBECOMPLETE_VBE_POPUP_CLASS=类名` 追加（探测与避让都用这份
      
    清单）；若成员列表那一侧仍撞车，再用 `set VBECOMPLETE_VBE_YIELD_CLASS=类名` 追加到
      
    "让位清单"即可。
- **输入 `xl` / `mso` 没有任何提示（或该补的 `xl*` 常量补不出来）**：★v70 起这批
    
  **默认就是关的**（用户口径：内置枚举不用、嫌干扰）。想收回来先确认这几条：
  1. 是不是压根没开：`ENABLE_HOST_ENUMS=True` 或 `set VBECOMPLETE_HOST_ENUMS=1`
       
     （**这才是最常见的原因**）；
  2. 这批常量是**运行时从工程的"引用"里现读**的，读不到就整批不出现，而**不会**
       
     影响其它提示 —— 工程里得真有那两条引用（VBE 菜单 **工具 → 引用**，`Excel` 与
       
     `Office` 默认都在；被取消勾选过就会缺）；
  3. 家族前缀是**自动推导**的（能盖住该库一半以上成员的最长公共前缀），
       
     推导不出就**整库跳过**（例如 `stdole` 那种 `Checked` / `Color` 各说各话的库，
       
     故意不收 —— 它们全是通用词，收进来只会污染你自己的变量名）；
  4. 白名单模式：`VBECOMPLETE_HOST_ENUM_FAMILIES=xl` 只留这一族；
  5. 日志里搜 `host-enums:` —— 会写明每个库"推导出的家族前缀 + 保留多少条"，
       
     以及哪几个库因为"无家族前缀"被跳过。
- **提示里冒出一堆 `vb*` / `xl*` / `mso*`，觉得吵**：★v70 起**默认都不出**了 ——
    
  内置枚举常量（`vb*`）用 `ENABLE_VBA_CONSTANTS`、宿主枚举（`xl*` / `mso*`）用
    
  `ENABLE_HOST_ENUMS` 控制，两个都默认 `False`。若不慎打开了又觉得吵：
  - 只要别把它们打开就行（默认口径）；
  - 只想要某一个家族：`set VBECOMPLETE_HOST_ENUM_FAMILIES=xl`；
  - 打开状态下的防噪规则（**没打开时用不上**）：它们只在你**敲出家族前缀**时才出现
      
    （`xl` / `xlu` / `mso`），输 `count` / `cell` / `range` 这类词**一条都不会多出来**；
      
    敲了前缀之后也要打满 **4 个连续字符**才开始接受跳着命中（`xlworkfaul` →
      
    `xlWorkbookDefault`），所以 `xlm` / `xlc` 这种三两个字符的输入不会炸出几百条。
- **打 `ms` 不提示 `MsgBox`、打 `Dim` 不提示关键字 —— ★v96 起这才是问题**：
    
  v96 起关键字与内建函数/数据类型已默认收进候选池（"把 vba 关键字、函数名这两部分
    
  也加入到提醒列表里"），如果这两个开关**又被关掉了**就会退化成 v77 的口径 ——
    
  候选池只剩你自己工程里的名字。逐批开关（改完 `stop.bat` → `run.bat` 生效）：
    
  内建函数 + 内建类型 `set VBECOMPLETE_VBA_BUILTINS=1`、
    
  关键字 `set VBECOMPLETE_VBA_KEYWORDS=1`、
    
  `vb*` 枚举 `set VBECOMPLETE_VBA_CONSTANTS=1`、`xl*` / `mso*` 用
    
  `set VBECOMPLETE_HOST_ENUMS=1`。四个开关互相独立，开哪个只影响哪一批。
- **自己的变量名被语言自带的名字压过去了（v96）**：不该发生，若发生请报一下触发时
    
  打的词。现在同分（命中 kind / 起点 / 跨度都相同）时**优先排你自己工程里的名字**，
    
  名字长短只在两边都是语言自带、或都是你自己的名字时才拿来比。
- **打两个字母冒出的候选比以前多**：v71 起那 260 来个内建名字允许"跳着打"了
    
  （`ve`→`VarType`、`vr`→`VarType`），代价是 `se` / `ce` / `le` / `re` 这类输入会多出
    
  几条；首字母对不上的仍被挡掉（`xl`→`Explicit`、`ms`→`Implements` 不出）。
    
  多出来的全部落在 `kind 0` 档，**不会顶掉**精确 / 前缀 / 连续命中 —— 打 `ms` 第 1 个
    
  仍是 `MsgBox`；★v96 起这条是**默认口径下就在生效**的。
    
  嫌多就用 `set VBECOMPLETE_BUILTIN_SCATTER_MIN=4` 退回 v61~v70 的老口径。
- **某个"用过但没声明"的变量名不再提示了（v75）**：这是**按模块**生效的 ——
    
  该模块的**第一行附近写了 `Option Explicit`**（强制声明），于是只用过、从没
    
  `Dim` 过的名字不再进池子（那种写法在该模块里是编译错误）。
    
  逐条排查：
  1. VBE 里打开那个模块，看顶部有没有 `Option Explicit`（注释掉的**不算**）；
  2. 想让它照旧提示：给这个名字补一行 `Dim`，或整批回到旧行为 ——
       
     `set VBECOMPLETE_IMPLICIT_HONOR_EXPLICIT=0`；
  3. 只想要"完全不收隐式变量"（连没写 `Option Explicit` 的模块也不收）：
       
     那是另一个更老的开关，改源码里的 `vbe_bridge.ENABLE_IMPLICIT_IDENTIFIERS`。
       
     日志里搜 `不收集隐式变量` —— 被闸掉的模块会逐行列出来
       
     （`mod=CopyPicturesToCells Option Explicit -> 不收集隐式变量`）。
- **`xl` 后面只打两个字母（`xlde` / `xd`）补不出 `xlWorkbookDefault`**（**打开**宿主
    
  枚举时才会遇到）：这是**故意的**，别再放宽 —— 放宽了也不会出现，只会更糟。
    
  实测真机 4538 条：
    
  `xlde`（家族前缀 + 2 字母）若接受"跳着凑"，会命中 731 条，而目标排在**第 291 位**；
    
  连家族前缀都不要求（`xd`）则是 1032 条、目标排**第 450 位**。
    
  候选窗一屏只有 15 行 —— 目标躺在第 291 位 = 翻 20 屏也看不到，还会把
    
  `ms`→233 条、`open`→484 条这类噪音全带回来。
    
  **原因不是规则太紧，是 `xlWorkbookDefault` 对这种输入本来就是"弱匹配"**：
    
  `xlDe` 对 `xlDefault` / `xlDelimited` 是连着打中的，对它却跳过了 8 个字符。
    
  想让它当场浮上来，就**连着打 4 个字母**：`xlwo`（9 条，可见）/ `xlwork`（31 条，第 9）/
    
  `xlworkf`（2 条，第 2）/ `xlworkfaul`（1 条，第 1）。
- **`Shift+↑` / `Shift+↓` 只是选中了一行、光标没"干净地上移"**：说明这一下没被我们
    
  接管，VBE 按原生语义（扩展选区）处理了。三种可能：
    
  ① 跑的是 v78 之前的代码（`stop.bat` → `run.bat` 重新加载）；
    
  ② 设了 `VBECOMPLETE_NO_SHIFT_NAV=1`（去掉即可）；
    
  ③ 当时焦点不在代码窗格、或 COM 正处于失败退避 —— 这时我们**刻意不吞键**，
    
  把按键原样交回 VBE。日志里搜 `navline:` 能直接看到第 ③ 种
    
  （`navline: COM 未落成 -> 按键原样还给系统`）。
- **括号 / 引号不想自动配对**：`set VBECOMPLETE_NO_AUTOPAIR=1`。
    
  若只是偶尔想只敲半边：先按一下 `"` 补出一对、光标在中间，直接输入内容即可；
    
  结对后按 `"` / `)` 是"跨过去"，不会多出字符。
- **`Call` 后面按 Tab 没补出 `()`、手敲 `(` 也像没反应**：★v102 已查明——
    
  **这不是 bug，是 VBA 的规范**。`Call foo()` 里的空括号会被 **VBE 自己立刻
    
  删掉**，`Call foo` 才是标准写法（有参数时 `Call judge(1, 2)` 括号才保留）。
    
  所以我们的补全**刻意不给 `Call` 位置补括号**、自动配对也**不接管**这一行的
    
  `(`，把按键原样交给 VBE。想带参数就这么写：`Call judge` + 空格 + 手打
    
  `(1, 2)`；或者干脆去掉 `Call` 直接写 `judge 1, 2`。
    
  ⚠️ 别用 `VBECOMPLETE_NO_AUTOPAIR=1` 绕开 —— 那会把正常位置的配对一起关掉。
- **补全关键字后没自动补空格（或反过来，不想补）**：★v103b 新增——补全
    
  `pub` / `func` / `sele` 这类关键字时会自动带一个空格（`public `）。两个方向查：
  - **想要却没有**：先确认 ① 是 v103b 之后的代码（`stop.bat` → `run.bat`）；
      
    ② 没设 `VBECOMPLETE_AUTO_SPACE=0`。仍没有的话，多半是**注入通道没接上** ——
      
    这个空格是"写完行、光标就位后**注入一个空格按键**"实现的（真机实测 VBE 会把
      
    `ReplaceLine` 写进去的行尾空格立刻 trim 掉，改行文本没用），注入函数由
      
    `main.py` 交给后端；开 `VBECOMPLETE_LOG=1` 看有没有
      
    `apply_completion: want_space=... AUTO_SPACE=... space_at=...` 这行即可定位。
  - **不想要**：`set VBECOMPLETE_AUTO_SPACE=0`（只关这一个功能，别的都不受影响）。
- **在 `Function` 里给函数自己赋返回值（`MyFunc = ...`）时，`MyFunc` 后面没补 `()`**：
    
  ★v103d 起这是**刻意的**（用户口径，原话："在 function 函数中，再给 function 赋返回值时，
    
  此时后面不应该自动补全括号"）。VBA 里函数名在**自己体内**代表的是"返回值的那个变量"，
    
  不是一次调用 ⇒ 补成 `MyFunc() = 5` 直接是语法错误（VBE 会报"不能给函数赋值"）。
    
  判据是纯函数 `engine._is_own_proc_name`（补全词 == `ctx["proc_name"]`，比之前先剥掉
    
  同名过程的 `#序号`）；在**别的过程里**写 `x = MyFunc` 照旧补 `()`。
    
  想要回老行为：把 `engine._completion_followup` 里那句
    
  `if _is_own_proc_name(low, enclosing_proc): return False, False` 去掉即可。
- **补全 `Sub` 之后没补 `()`、只多了一个空格**：★v103c 起这是**刻意的** —— VBA 里
    
  `Sub` 是无返回值的语句，标准写法不带括号（`Sleep 1000`、`Foo 1, 2`），而且
    
  `Foo()` 里的空括号**会被 VBE 立刻删掉**（见上面 `Call` 那条实测表），补了等于白做；
    
  只有 `Function` 才补 `()`，`Property` 两者都不补。判据是**声明里的关键字**
    
  （`parser.extract_proc_kinds`）—— 想让某个过程补括号，就把它声明成 `Function`；
    
  真机实测（独立 Excel 实例 + 真 `CodeModule`）五种情形全对。
- **`对象.` 后面不弹提示了（或反过来，想恢复）**：★v103c 起**刻意不出** —— 点号后面
    
  该出现的是"这个对象的成员"，而我们只给得出裸名（变量名 / 过程名 / 关键字），挂在那儿
    
  就是噪音（用户口径："现在会提示函数名，变量名这些，按道理提示的应该是类或者对象的
    
  成员"）。VBE 自己在同一位置会弹「自动列出成员」，按真实类型解析，比我们准。
  - **想恢复旧行为**（出候选 + 按声明类型收窄）：`set VBECOMPLETE_MEMBER_POPUP=1`。
  - `Ctrl+Space` 点名要的列表**不受影响**，在哪儿都照弹。
- **定义变量 / 函数 / 过程时也弹候选列表（或反过来，想恢复）**：★v105 起**刻意不弹** ——
  造新名字的位置本来就没有"既有符号"可补，弹出来的都是别人的变量名 / 过程名 / 关键字，
  纯噪音，还会盖住你刚敲的字。IDEA 也是这个口径。
  - 覆盖范围：`Dim` / `Static` / `Const` / `Public|Private|Global` 变量与常量、
    `Sub` / `Function` / `Property` / `Declare` / `Event`、`Type` / `Enum`
    （**含**"只敲了关键字、名字还没开始打"的中间态，如 `Sub ` / `Public Function `）。
  - **不受影响的两处**：① `As` / `New` 之后的**类型名**位置照常提示类型名
    （那里是在**引用**类型，不是造名字）；② `ReDim` 照常提示已有数组名。
  - **想恢复旧行为**（声明行照常出候选）：`set VBECOMPLETE_DECL_POPUP=1`。
  - `Ctrl+Space` 点名要的列表**不受影响**，在哪儿都照弹。
- **打完 `(` 光标没落在括号中间**（比如 `… = RGB(` 之后光标跑到别处）：
    
  ★v79 已修。成因是 VBE 的自动语法检测把整行重排了（补空格 / 改大小写），
    
  按老位置落光标就会偏。现在会在读回重排后的行、按"插入点左边的代码"重新
    
  定位那一对符号。**若还遇到**，把这一行原文连同「光标落到了哪」一起发我即可 ——
    
  需要区分的就是两种情况：VBE 根本没重排（那是我们算错了写入位置），
    
  还是重排了但指纹与差分都没认出来（`定位=None`）。

    而 `Else` / `Case` 本来就是块**里面**的（v81 起会被拉回块头那一带：`Else`
      
    与 `If` 齐平、`Case` 从 v83 起比 `Select Case` 深一级），这趟扫描里
      
    **必须跳过**；整行注释同理（注释根本不参与块结构）。
  - 修法：`vbe_bridge._own_closer_below` 里遇到 `Else` / `ElseIf … Then` / `Case …`

- **在 A 过程里输入，却提示出 B 过程的局部变量（跨过程泄漏）**：v79c / v79d / v79e
    
  各修了一条路径，现在都不该再发生。典型症状：`Sub test()` 里写过 `Set targetSheet = …`
    
  （没写 `Dim` 的隐式变量），另起一个过程、在**模块级**输入 `Sub test`，弹窗里冒出
    
  `targetSheet`。
  - **v79c（过程归属）**：宿主 VBE 的 `ProcOfLine` 会把你**光标所在行**归给**邻近过程** ——
      
    `End Sub` 那一行、两个过程之间的空行、以及**模块声明区里第一个过程头之上**的行，全都
      
    算到前一个过程头上，于是"别处的局部变量"被当成"当前过程的"。现在过程归属**优先用
      
    文本扫描**（`parser.proc_at_line`），COM 只兜底，且兜底结果还要过一道**归属校验**
      
    （`parser.proc_owns_line`：过程头必须在光标上方、中间没有 `End Sub` 之类的收尾）。
      
    落在过程外的行一律判为"没有当前过程"，只提示模块级 / 公有的名字。
  - **v79d（过程头那一行）**：光标停在**过程头**上（比如正在写 `Sub test`）时，整行仍被
      
    当成了"当前过程"—— 新起的名字恰好与模块里已有的过程同名，那个过程的局部变量就全
      
    冒出来了。现在**过程头那一行属于"声明"，不算过程体**（`parser.is_proc_header_line`）：
      
    那一刻按模块级算，只提示模块级 / 公有的名字。判据是"这一行自己是不是 `Sub` /
      
    `Function` / `Property Get|Let|Set` 头"。
  - **v79e（同名过程各自成域）**：同一模块里出现**两个同名过程**时（VBA 编译期会报
      
    "二义性名称"，但你在敲新过程头时会短暂处于这个状态），记录里只存"过程名"，
      
    第一个过程和第二个过程的局部变量在过滤时**无法区分** —— 于是第二个过程的体内会
      
    提示出第一个过程的 `targetSheet`。现在过程在作用域过滤里用一个**键**标识：
      
    **第 1 次出现用原名，第 2 次起写成 `名字#序号`**（`parser._proc_scope_key`；
      
    名字不重复时键就是原名，既有行为一点都不变）。真机验证：模块里两个 `Sub test`
      
    时，第 2 个过程内 `proc='test#2'`，不再提示第 1 个过程的 `targetSheet`。
  - **v79e（声明名不再被改写）**：v79d 那版把光标压着的声明名抹成**等长下划线**。
      
    方向没错（行结构不能坏），做法有害 —— 名字只有**一个字符**时（`Sub t`），行尾
      
    正好是"空格 + 下划线 + 换行"，而那是 VBA 的**行继续符**形状：这一行被当成续行、
      
    把**下一行吞进同一行**，过程头就没了、其后整段过程体失去归属，里面的变量
      
    **降级成模块级**，全模块到处都能提示 —— 正是"过程级的变量都泄露到其他过程"。
      
    现在**声明名一个字都不动**（`_blank_ident_at` 对"正在声明的名字"原样返回）；
      
    "打什么不提示什么"交给引擎现成那两道防线（`decl_names` 精确剔除 + 回声防护）。
      
    配套的一处必须同步：现场证据扫描要**显式要求抹词**（`names_outside_caret(…, True)`），
      
    否则那个词会把自己算成"别处也出现过"的证据，幻影词又会被提示回来。
  - 自查：光标停在过程头那一行时**本来就不提示该过程的局部变量**（那是声明位置）；把
      
    光标移进过程体，局部变量照常提示。同一模块里写两个过程时，各自过程体内**只提示
      
    各自的**变量。
  - 提醒：VBA 不允许同一模块里有两个同名过程（编译会报"二义性名称"）。工具现在能把
      
    它们分开对待，但真正要跑得给其中一个改名。
- **输入新变量名时提示出它自己 / 回退删字时提示出旧的长名字（类模块里也会遇到）**：
    
  v87 已修。典型症状：在类模块（或窗体 / Sheet / ThisWorkbook）里输入一个**刚起的名字**，

## 更新后如何生效

Python 在**启动时**把 `.py` 读进内存，只替换文件而不重启进程，跑的仍然是旧代码。
  
所以更新后请务必：**`stop.bat` → 覆盖文件 → `run.bat`**。
