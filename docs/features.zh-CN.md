### 功能说明

- **`对象.` 之后只提示这个对象的成员**（v98）：`Set c = New Cls` 之后打 `c.te`，
    
  候选里只有 `Cls` 的成员（`TempField` / `TestMethod` …），**不会再混进本过程的
    
  局部变量**（`temp` 之类）或别的模块的名字。
  - 正常的成员访问仍然**优先让位给 VBE 自己的「自动列出成员」**（列得最全、
      
    带原大小写）。只有 VBE 解析不出这个对象的类型时（刚敲完 `New Cls` 还没编译，
      
    或宿主对象）它一个窗都不弹，宽限期到了才由我们补位—— 补出来的候选就按
      
    上面那条口径收窄，不再是全工程。
  - 判不出来就**不收窄**（宁可多提示也绝不挡掉）：类型没写明、隐式变量、
      
    宿主对象类型（`Range` 这类不在你的工程里）、类型名拼错。
  - 搜不到该类型的成员时也退回全工程候选，不会给一个空窗。
- **补全函数 / 过程时自动补括号，光标落在括号内**（v98）：选中一个
    
  `Sub` / `Function` / `Property` 名（或 VBA 内建函数如 `MsgBox` / `Left`）
    
  按 `Tab`，写回成 `DoWork()`，光标停在两个括号中间，可以直接敲参数。
  - **只在调用点补**：`x = DoWo` → `x = DoWork()`、`f = DoWo` → `f = DoWork()`。
      
    声明行由 VBE 自己补，不插手。
  - 🔴 **★v102：`Call 过程名` 这个位置【刻意不补括号】** —— 而且这不是我们的取舍，
      
    是 **VBA 的规范**：`Call foo()` 里的空括号会被 **VBE 自己立刻删掉**，
      
    `Call foo` 才是标准写法（有参数时 `Call foo(1, 2)` 的括号才会保留）。
      
    真机实测（独立 Excel 实例 + 真 `CodeModule`）：
    | 写进去                    | 立刻读回                             |
    | ---------------------- | -------------------------------- |
    | `    Call judge()`     | `    Call judge` ← 括号被 VBE 删掉    |
    | `    Call judge(1, 2)` | `    Call judge(1, 2)` ← 有参数，保留  |
    | `    judge()`          | `    judge()` ← 不在 `Call` 语句里，保留 |
    ⇒ 这个位置上我们**做任何括号动作都是白做**，而且是最坏的那种白做：用户看到的
      
    是「按了没反应」。**修法就是什么都不做** —— 补全不补括号、自动配对不接管，
      
    把按键原样交给 VBE（它自己插入 `(`，用户接着输参数时会得到
      
    `Call judge(1, 2)` 并保留）。判据只看**行首是不是 `Call` 关键字**
      
    （`_in_call_stmt`），所以 `Call obj.Method` 也一并挡掉；
      
    `Callback x` / `CallCount = 1` / `x = Call foo` 这些不会被误伤。
      
    ⚠️ **不要去设 `VBECOMPLETE_NO_AUTOPAIR=1` 绕开这个** —— 那是全局关掉自动配对，
      
    正常位置的 `(` 也不会配对了。
  - **类型名位置绝不补**：`Dim n As Lon` → `Dim n As Long`（不是 `Long()`，
      
    补了编译不过）；`Set x = New Lon` 同理。
  - 变量名不补括号（`temp` → `tempValue`，不加 `()`）—— 只有过程/函数该补。
  - **语言关键字绝不补括号**（v99）：`Public` / `Private` / `Dim` / `Call` 之类
      
    补成 `public()` 编译不过。判据用**白名单**：只有 `vba_builtins.BUILTIN_FUNCTIONS`
      
    那 171 个内建函数才算可调用，**再叠一道"不是内建数据类型"的排除**。
      
    ⚠️ 这两道判据问的是**两个不同的问题**（"VBA 有没有这个函数" vs
      
    "这个名字会不会被当成类型用"），**不能合成一条** —— 合成一条就退回 v98
      
    那个 `public()`；只留白名单则 `String` / `Date` 漏成 True（它们在 VBA 里
      
    **既是类型名也是函数**，`String(5, "ab")` 是合法代码）。类型位置最终由上面
      
    那条 `_is_call_site` 闸门挡住。
  - 右边本来就紧跟 `(` 的（`x = DoWo(1)`）不重复补。
  - **让位期间按 Tab 补进来的过程名也会补括号**（v100）：在**点号成员 / 类型位置**
      
    这类真正会让位的地方，VBE 自己弹着「自动列出成员」、我们全程让位 ⇒ 那一下
      
    Tab 是打给 VBE 的列表的，我们的 `accept()` 从没被调用，而 **VBE 插名字时
      
    不带括号**。现在会在确认"这一行只被插入了一段标识符"（v90b/v91 已有的判据）
      
    之后，把光标处那个整词交给同一个 `apply_completion(..., want_parens, want_space)`
      
    —— ★v103c 起这两个标志由 `_completion_followup` 按**声明**给出（`Function` 补
      
    括号、`Sub` 补空格、`Property` 都不补）。⚠️ 要判的是**光标处的整个词**，
      
    不是"插入的那一段"—— VBE 是把半截词**补长**（`jud` → `judge`），公共前后缀
      
    一算，插入段只是差量 `ge`，拿它判"是不是过程名"必然判否。
      
    ⚠️ ★v103c 起**点号成员**位置我们不再出候选（默认），所以实际还会走到这段的
      
    只剩下**类型位置**（`As ` / `New `）那一类。
      
    ⚠️⚠️ **v101 更正**：`Call ` 之后我们**并不让位**（实测
      
    `vbe_list_expected("    Call ", 10)` 返回 `False` —— 它只认 `标识符.` 与
      
    `As `/`New ` 两种位置），`Call jud` 时我们的窗是弹着的、Tab 走的是
      
    `accept()`，**根本轮不到这段**。所以 `Call` 那个故障和这里无关（v100 曾把
      
    修复挂在这里 ⇒ 白修一轮），它的真正成因见上面 ★v102 那条。
  - 想关掉：`set VBECOMPLETE_AUTO_PAREN=0`
- **输入即提示，实时过滤**：输入字母/数字/`_` 即弹列表，继续输入会实时过滤。
- **提示只在【代码窗格】里出现**（v64）：VBE 里的**属性窗口、工程窗口、窗体设计器**
    
  都不是写代码的地方，在那里打字/改属性值时**不会**冒出候选窗。
    
  判据是"VBE 线程里当前拥有键盘焦点的窗口，父链上有没有**代码窗格**"（窗口类
    
  `VbaWindow`）—— 比"前台窗口标题里有没有 Microsoft Visual Basic"精确得多，
    
  后者对上面那些子窗口**一律**返回真，正是"在属性窗口里改属性值时冒出提示"的成因。
    
  焦点不在代码窗格时：**不弹候选**、并**收起已经挂着的候选窗**，也不会替你做
    
  自动配对 / `Shift+Enter` 换行（免得把字符写进代码窗格）；`Ctrl+Space` 同样不接管。
    
  判不出来时（找不到 VBE 主窗口 / 宿主窗口类名不同）退回旧判据，绝不"拿不准就拦"。
    
  想退回旧行为：`set VBECOMPLETE_NO_CODE_AREA_GATE=1`。
- **模糊匹配：不要求从首字母开始**。只要输入的几个字符**按顺序**出现在名字里就会提示，
    
  **命中的字符标红**，一眼看出为什么它被匹配到。例如定义了 `dataArr` 和 `dataSheet`：
  - 输入 `ts` → 提示 `dataSheet`（da**t**a**S**heet，`datasheet` 里没有连续的 `ts`，
      
    所以按**词边界**命中两个 `t`/`S`）；
  - 输入 `ta` → 同时提示 `dataArr` 和 `dataSheet`（两边都是连续的 **ta**）；
  - 输入 `ds` → 提示 `dataSheet`（**D**ata**S**heet，camelCase 词首缩略）；
  - 输入 `arr` → 提示 `dataArr`（data**Arr**，优先命中连续块，而不是散着凑字母）。
      
    候选按「精确 > 前缀 > 词首缩略 > 连续块 > 分散」排序，同级再比命中是否更靠前、
      
    跨度是否更小、名字是否更短——最像的永远排第一，列表不会因为放开了模糊匹配就变乱。
      
    输入普通前缀（如 `num`）时结果与纯前缀匹配完全一致，不会平白多出一堆噪音。
- **★v103 排序再叠两层 IDEA 式相关度**（命中质量完全相同、名字长短也一样时的"决胜局"）：
    
  完整评分键（越大越靠前）是
    
  `命中质量(kind/首个命中位置/跨度) > 作用域档位 > 最近使用 > 是不是语言自带 > 名字长度`。
  - **作用域就近**（局部变量优先，对标 IDEA 的 "local scope first"）：同一个词在本过程
      
    的局部变量 / 形参（档位 **4**）> 本模块的模块级名字（**3**）> 别的模块的 `Public`（**2**）
      
    中同时命中、且**命中质量与长度都相同**时，本过程那个排前面。此前作用域只用来**过滤**
      
    （可见性），不参与**排序**，于是"别处那个恰好先被收进来"就会压过你的局部变量。
      
    想关掉：`set VBECOMPLETE_NO_SCOPE_RANK=1`。
  - **最近使用**（对标 IDEA 的 "recently used"）：你刚用 `Tab` 确认过的名字，下次再命中时
      
    排到同分候选的前面（`accept()` 里记一笔）。只记最近 `VBECOMPLETE_RECENT_MAX`（默认 64）个，
      
    超出按最旧 1/4 批量淘汰。想关掉：`set VBECOMPLETE_NO_RECENT_RANK=1`。
  - ⚠️ 这两层都只放在**决胜局**（命中质量之后、长度之前）—— 命中质量永远第一优先，
      
    所以"打了 `msgbox` 就选 `MsgBox`"这类强匹配不受影响；只有真正同分时才看出差别。
- **★v103b 补全关键字时自动补一个空格**（对标 IDEA 的关键字补全）：
    
  输入 `pub` / `func` / `sele` 这类前缀按 `Tab`，写回的不只是关键字本身，后面还跟着
    
  一个空格 —— `public `、`function `、`select `，可以直接接着敲下一个词。
  - 覆盖哪些词：**语言关键字**里除掉少数几个不该补的，共 62 个。排除的是：
      
    经常是**整行最后一个词**的（`Else` / `Next` / `Loop` / `Then` / `Wend` / `Stop` /
      
    `Return` / `Explicit` / `Do` / `Resume`）、后面紧跟**点号**的（`Me` / `Debug`）、
      
    本身就是**完整表达式**的（`True` / `False` / `Nothing` / `Empty` / `Null`）。
      
    ⇒ 用**排除法**：以后关键字表加词，新词自动获得补空格能力。
  - ⚠️ 实现上有一个真机坑：**VBE 会把 `ReplaceLine` 写进去的行尾空格立刻 trim 掉**
      
    （实测写 `"    public "`、读回 `"    public"`）⇒ 不能靠改行文本，只能在写完、
      
    光标就位之后**注入一个空格按键**（实测注入的空格会被保留，后面接着打字就是
      
    `public Sub`）。注入函数由 `main.send_char` 提供，没接上就静默跳过 —— 绝不会
      
    半途改坏代码。
  - 工程里的变量名 / 过程名**不补**空格（那是噪音）；用户自建的过程走"补括号"那条路。
      
    关键字与内建函数两张表交集为空，所以"补空格"与"补括号"互斥、不会撞车。
  - 想关掉：`set VBECOMPLETE_AUTO_SPACE=0`。
- **★v103c 补全过程名时，按它是 `Sub` 还是 `Function` 决定后面跟什么**（对标 IDEA：
    
  有返回值的方法补 `()`，无返回值的按语句写）：
  - **`Sub` / `Declare Sub` → 补一个【空格】**。VBA 里 Sub 是无返回值的语句，标准写法
      
    本来就不带括号（`Sleep 1000`、`Foo 1, 2`）；就算补了空括号 `Foo()`，**VBE 也会
      
    立刻把它删掉**（见上面 v102 那张实测表）—— 补了等于白做，用户看到的是"按了没反应"。
  - **`Function` / `Declare Function` → 补一对 `()`**（按调用表达式写：`x = GetName()`）。
  - **`Property` → 都不补**（`x = p.Name` / `p.Name = Name` 两种用法都不带括号）。
  - **`Call 过程名` 语句里两者都不补** —— 那个位置的实参写法不同（`Call foo(1, 2)`），
      
    补一个尾随空格纯属无意义字符；判据与"不补括号"用的是同一个 `_in_call_stmt`。
      
    真机实测（独立 Excel 实例 + 真 `CodeModule`，直接调真 `apply_completion`）：
    | 场景                             | 写进去                 | 读回                         |
    | ------------------------------ | ------------------- | -------------------------- |
    | Sub（`DoWo`→`DoWork`）           | `    DoWork` + 注入空格 | `   DoWork` ← 空格被 VBE 保留   |
    | Function（`CalcVa`→`CalcValue`） | `    CalcValue()`   | `    CalcValue()` ← 光标落进括号 |
    | Property（`Titl`→`Title`）       | `    Title`         | `    Title` ← 都不补          |
    | Sub 右边已有空格                     | `    DoWork 1`      | 不重复注入                      |
    | `Call DoWo`                    | `    Call DoWork`   | 不补空格                       |
  - 判据是**纯文本**的（`parser.extract_proc_kinds`，与认过程名用的是**同一批**正则，
      
    所以不可能出现"有候选、却查不到它是什么"）；后端没提供这个接口（旧式构造）时
      
    退回老口径（过程名一律补括号）。
- **候选池 = 你这个工程里真实存在的东西 + VBA 关键字 + 内建函数**（★v96，用户口径
    
  "把 vba 关键字、函数名这两部分，也加入到提醒列表里。枚举类型就不要加了"）。具体是：
  - **收**：**变量名**（含没写 `Option Explicit` 时"用过即存在"的那种）、
      
    **你自己写的 `Sub` / `Function` / `Property`**、**组件名**（标准模块 / 窗体 / 类模块）、
      
    **窗体控件名**，**外加 VBA 语言关键字**（`Sub`、`Dim`、`If`、`For`、`Set` …）与
      
    **内建函数 / 内建数据类型**（`MsgBox`、`Left`、`Split`、`Long`、`String` …，约 260 个）。
  - **不收**：**一切枚举** —— VBA 内建的 `vb*`（102 条）和宿主类型库的 `xl*` / `mso*`
      
    （4500+ 条）。用户原话："枚举类型就不要加了，枚举加上，就会太多了。"
      
    （v70 起的判断，v96 明确维持。）
  - 想改口径（任一都是 `set VBECOMPLETE_xxx=0|1`，改完重启生效）：
    - **内建函数 + 内建数据类型**：`VBECOMPLETE_VBA_BUILTINS`（默认 **1**）；
    - **语言关键字**：`VBECOMPLETE_VBA_KEYWORDS`（默认 **1**）；
    - **VBA 内建枚举常量**（`vbCrLf`、`vbYes`、`vbOK` …）：`VBECOMPLETE_VBA_CONSTANTS`
        
      （默认 **0**）；
    - **宿主类型库枚举常量**：`VBECOMPLETE_HOST_ENUMS`（默认 **0**；
        
      只想留一族：`VBECOMPLETE_HOST_ENUM_FAMILIES=xl`）。
  - ⚠️ **四份清单一个字都没裁**，只按开关在收集侧取舍 —— 所以"关掉"不是"能力删除"，
      
    想开回来随时有效。
  - ★**你自己的名字一定排在语言自带的名字前面**（v96）：`decl` 同时命中
      
    `declaredVar`（你的变量）和 `Declare`（关键字），两者的**命中质量完全一样**
      
    （都是前缀命中、起点 0、跨度 4），但 `Declare` 名字更短 —— 纯按"名字短者在前"
      
    排的话，关键字会压过你自己的变量。所以评分键改成
      
    `命中质量 > 是不是语言自带 > 名字长度`：质量相同（kind / 起点 / 跨度都相同）时，
      
    先看是不是你自己工程里的名字，最后才比长短。精确命中不受影响
      
    （打了 `msgbox` 仍然直接选 `MsgBox`）。
  - 开回来之后，这些名字代码里 **一个字都没写过**也照样提示 —— 它们由语言运行时决定存在：
  ⚠️ 关键字与内建函数的**匹配口径比工程内名字紧**（不紧的话它们会淹掉你自己的名字）——
    
  只在 2~3 个字符的短输入下生效，4 个字符以上与工程内名字同一套规则：
  - 内建名字 + 关键字（约 260 个，v71 放宽）：**跳着打的时候，第一个字母必须与
      
    候选名的首字母相同** —— `ve`→`VarType`、`vr`→`VarType`（都是 v 开头）放行，
      
    而 `xl`→`Explicit`、`ms`→`Implements`（首字母对不上）挡掉。
      
    连续 / 前缀 / 词首缩略命中不受此限：`ms`→`MsgBox`、`vt`→`VarType`、
      
    `slct`→`Select` 照常。想退回 v61~~v70 的老口径（2~~3 字符只留连续/前缀命中）：
      
    `set VBECOMPLETE_BUILTIN_SCATTER_MIN=4`；
  - 宿主常量（约 4500 条，默认不收）：**必须从家族前缀开头**（`xl` / `mso` —— 这条不能松，
      
    正是它把 `ms` 带出 2365 条 `mso*`、`count` 带出上百条这类噪音整片挡掉的），
      
    再要求你**打进去过一段连续的名字片段（≥ 4 个字符）**：
      
    `xl`→`xl*`、`xlu`→`xlUp`、`mso`→`mso*` 照常，`ms` 只出 `MsgBox`（绝不带出
      
    `mso*`）、`count` / `cell` / `range` 一条 `xl*` 都不会多出来；
      
    而**跳着打**也能命中（v68）—— `xlworkfaul` → `xlWorkbookDefault`、
      
    `xlcell` → `xlCellTypeVisible`（前缀）`+ xlLastCell`（跳步，永远排在前缀之后）。
      
    输入不足 4 个字符时退化成纯前缀，与只认前缀时**一模一样**，不会平白多出噪音。
      
    （v69 给这一段加了一层廉价的"4 连片断"预筛：候选集一字不变，宿主那段耗时
      
    约降到三分之一，整条匹配快 1.5~2.8 倍。见"跳着打补不出来"那条。）
- **打全名照样提示**：名字打全了列表不会消失（`Sub tes` → `Sub test` 始终提示 `test`），
    
  包括**正在写函数/变量声明行**的时候——只要那个名字在工程里真实存在就一直提示。
    
  真正会被剔掉的只有"幻影词"：工程里哪都不存在、只是你正在敲的那几个字符
    
  （比如回退删出来的 `numA`），那才叫"提示自己"。
  - ★v87：「真实存在」判的是**在你这个位置能不能裸名引用**，不是"工程里有没有出现过
      
    这几个字"。**类模块 / 窗体 / 文档模块（Sheet、ThisWorkbook）里的模块级成员默认是
      
    私有的**，别的模块只能写 `实例名.成员` 或 `UserForm1.控件`——你在别处把它们当裸名

  会顺手把收尾也补出来，光标停在中间那行（缩进已经好了），可以直接写块内容：
  | 写这一行 + 回车         | 自动变成                                    |
  | ----------------- | --------------------------------------- |
  | `If i = 1 Then`   | `If i = 1 Then` / 缩进好的一行 / `End If`     |
  | `With rng`        | `With rng` / 缩进好的一行 / `End With`        |
  | `Sub Foo()`       | `Sub Foo()` / 缩进好的一行 / `End Sub`        |
  | `Select Case x`   | `Select Case x` / 缩进好的一行 / `End Select` |
  | `For i = 1 To 10` | `For i = 1 To 10` / 缩进好的一行 / `Next`     |
  | `Do`              | `Do` / 缩进好的一行 / `Loop`                  |
  | `While x`         | `While x` / 缩进好的一行 / `Wend`             |

    `Next`，外层那个由**它自己那行**回车时补 —— 两层各管各的，不会"只补外层"。
      
    双层 `If` / `Do` / `With` / `Select Case` 同理。判据是：下方那个更浅的同类收尾，
      
    若它上面还压着一个**同类块头**（说明这个收尾是外层的），就不再重复补（见
      
    `vbe_bridge._closer_owner_above`）。

    **缩进为 0**，下面紧跟着的就是 `Sub …` 这些**同级**（同样缩进 0）的过程。旧判据
      
    把"同级"一律当成"下文已经在写了"，所以从不补（v79c 只放开了"缩进 0"这一档）。
      
    v80a 换成**配平扫描**：从块头往下数，遇**同类块头 +1 / 同类收尾 −1**，数完**归零**
      
    就说明"下面已经挂着我自己的收尾"⇒ 不补；**归不了零**⇒ 补（见
      
    `vbe_bridge._own_closer_below`）。于是 `Type` / `Enum` 的 `End Type` / `End Enum`
      
    照样补得出来，而 `Sub` / `Function` 这类**紧跟一个同级过程头**的情况仍然不补
      
    （下面那行不是收尾，本来就不该硬塞收尾）。
      
    ⚠️ 这一版修的正是"**在已有的块上面再补一个块**"：先写了一个 `For` 并补出 `Next`，
      
    再回头在它**上面**加一个新的 `For` —— 旧判据看到"下面那个同级缩进的行不是收尾"
      
    就不补了，现在按"我自己有没有收尾"判断，照补不误。
  - **不补的**：`Else` / `ElseIf … Then` / `Case …` 是块**内部**的分支，往下一行
      
    只是同级的分支体；`#If … Then` / `#Else` 条件编译必须配 `#End If`，
      
    替你写个裸的 `End If` 反而把代码写错 —— 这些一律只缩进、不补。
  - **不该补的时候绝不硬塞**：下面**已经挂着本块自己的**收尾（`End Sub` / `Next i` /
      
    `Loop While x`…，隔着空行也算 —— 判据是配平扫描能归零），或者这块的**下文已经在写了**
      
    （下面第一个非空行的缩进**比块头浅**，且那个更浅的同类收尾确实属于外面那一层）——
      
    都只缩进、不补，免得把你已有的代码顶开。所以"在 `Sub` 里补 `If … Then`"这种最常见的
      
    情形是对的：下面压着 `End Sub` 比 `If` 浅，正是"这块还没内容就该结束"，收尾就补在这儿。
  - **分支行 / 注释不算"本块到此为止"（v82）**：配平扫描遇到的
      
    `Else` / `ElseIf … Then` / `Case …`（含 `#Else` / `#ElseIf … Then`）和整行注释，
      
    都**直接跳过**、继续往下找本块的收尾 —— 它们本来就在本块**里面**（注释根本不参与块结构）。
      
    ⚠️ 这一版修的正是"**已经补过收尾又补一个**"：`If … Then` 回车补出 `End If`，
      
    接着写了 `Else`（v81 会把它拉回与 `If` 同级），再回到 `Then` 那行行尾按回车 ——
      
    旧判据把同级缩进的 `Else` 当成"同级的别的代码 ⇒ 本块已结束"，于是**又补一个 `End If`**。
      
    `Select Case` 里的 `Case` 完全同理（v83 起它比 `Select Case` 深一级，这趟扫描里
      
    也一样跳过 —— 见 `vbe_bridge._own_closer_below`）。
  - **行标签 / 条件编译指令同样不算边界；扫描窗口也放宽了（v86）**：配平扫描还会跳过
      
    **行标签**（`1:` / `Retry:` —— 配 `GoTo 1` 用，VBA 惯例就是【顶格】写）和
      
    **`#` 条件编译指令**（`#If` / `#End If` / `#Const`…，同样惯例顶格）—— 这两类行的
      
    缩进跟所在嵌套层级**毫无关系**，拿它当"已经出了这一层"的证据，就会把下面真正躺着的
      
    `End If` / `End Sub` 当成不存在。另外"往下找本块收尾"的扫描窗口从 200 行放宽到
      
    600 行；万一过程比窗口还长（收尾落在窗口之外），判据按"**看不到就不补**"兜底 ——
      
    宁可少补一条（你自己敲一下就好），也绝不凭"没看见"变出**双份收尾**
      
    （`End Sub` 双份是直接编译不过的）。
      
    ⚠️ 这一版修的正是"**过程里写了很多代码之后，把光标移回 `Sub` 那行（或 `Then` 那行）
      
    按回车，又补出一个收尾**"：实测 `脚本.xlsm / 模块2` 的 `Sub 功能2()` 里那个顶格的
      
    `1:` 一次坑掉三处（`Sub` 行 / 外层 `For` 行 / `If … Then` 行各一次）。
      
    判据见 `vbe_bridge._indent_blind` 与 `closer_needed(truncated=…)`。
  - **`Shift+Enter` 也补（v88）**：上面这套判据现在**两条路都用** —— 回车那条要求
      
    光标在**行尾**，`Shift+Enter` 那条**不看光标在哪一列**（它本来就不拆行）。
      
    于是"把光标停在 `If … Then` 中间按 `Shift+Enter`"也能补出 `End If` 来。
      
    不是块头的行、或者下面已经挂着自己的收尾，仍然只插一行、不补。
      
    ⚠️ 这一版修的正是"**光标在代码中间按 `Shift+Enter` 不补块**"：
      
    同样是 `If … Then`，光标在行尾按回车能补、光标在中间按 `Shift+Enter` 不能 ——
      
    差别只在"回车那条路能不能接管"（不在行尾时它整件事作废，把按键还给 VBE，
      
    而 VBE 原生回车那时是**拆行**）。
  - **`Shift+Enter` 的缩进判定与回车同源（v89）**：`Shift+Enter` 那条路原先只在
      
    "**有收尾的块头**"上把新行缩进深一级（v88 那段"深一级"写在"要不要补收尾"的
      
    判断**里面**）—— 而 `Else` / `Case` / `#If … Then` 这三类恰恰是 `_block_kind`
      
    认的**块头**、却**没有收尾**（`block_closer` 返回 `None`，见上面"不补的"那一条），
      
    整行注释更不在话下，于是它们统统落回老口径（抄本行空白）。现在这一支的缩进统一
      
    由 `next_line_indent` + `branch_align` 算：注释行往上找第一个非注释行、块头深一级、
      
    `Else` / `Case` / `#Else` / `#ElseIf` **先把本行拉回它该在的层级**，空行不猜层级。
      
    ⚠️ 这一版修的正是"**按 `Shift+Enter` 换行不判定自动缩进，只有按回车才判定**"：
      
    同一条 `Else`（歪在块体那一级），回车会把它拉正、`Shift+Enter` 原先不会。
  - 想只留缩进、不要补收尾：`set VBECOMPLETE_NO_AUTOCLOSE=1`（两条路一起关；
      
    **缩进不受它影响**，见上一条）。
- **块内分支回车自动对齐**（v81；层级分档 v83）：`Else` / `ElseIf … Then` / `Case …` 这些
    
  **块内分支**在行尾按回车时，会先把自己拉回**该在的层级**，新行再深一级 —— 于是
    
  `Else` / `ElseIf` 与最近的 `If … Then` **齐平**、`Case` 比最近的 `Select Case`
    
  **深一级**（条件编译的 `#Else` / `#ElseIf` 与 `#If … Then` 齐平）：
  ```
  写 If 后回车：              接着写 Else 再回车：
      If x = 1 Then               If x = 1 Then
          |            ->          |            <- 这里是 Else 落下的位置
      End If                      End If

                              ->   If x = 1 Then
                                   Else         <- 自动拉回来，与 If 同级
                                       |        <- 光标停这儿（块体深一级）
                                   End If

      Select Case x
          Case 1                               <- 比 Select Case 深一级（v83）
              |                                <- 光标停这儿（块体再深一级）
      End Select
  ```
  - **为什么需要这一条**：`Else` / `Case` 也算"块头"（回车后要缩进一级），所以**这一下回车
      
    是我们在管**—— 而 VBE 原生回车本来会把刚敲完的那一行拉回它该在的层级。我们一接管，
      
    VBE 的自动对齐就没机会跑，`Else` 于是停在"块体那一级"上（正好是上面自动补完 `End If`
      
    后光标停的那一行）。这里补的正是这一下。
  - **层级按分支分档（v83）**：`Else` / `ElseIf` 与 `If` 齐平、`#Else` / `#ElseIf` 与
      
    `#If` 齐平，而 `Case` 比 `Select Case` **深一级**（VBA 惯用缩进，也正是 VBE 原生
      
    回车会整理成的样子）。v81 把 `Case` 也拉平到 `Select Case` 同级了 —— 已修正。
      
    用 Tab 或 2 空格缩进的工程跟着工程自己的缩进单位走。
  - 归属关系在 VBA 里**没有歧义**，所以不猜：`Else` / `ElseIf` 归最近的**还开着**的
      
    `If … Then`，`Case` 归最近的**还开着**的 `Select Case`。上方找不到归属者
      
    （`If x Then y = 1` 这种**单选 If**、`Else` 敲在 `If` 前面、`Case` 敲在 `Select Case` 前面）
      
    就**什么都不做**，维持老行为（本行不动、新行 = 本行缩进 + 一级）。
  - **只改行首空白**，行内一个字符都不碰；本行已经对齐时连改都不改。
      
    万一写不成（COM 抽风），这一下回车**原样还给系统**，绝不"半做"（不会只改一半）。
  - 回车那条路只在**行尾**触发；`Shift+Enter` 那条路（v89 起）**做同样的对齐**，
      
    而且不看光标在哪一列（它本来就不拆行）。
  - 想关掉：`set VBECOMPLETE_NO_BRANCH_ALIGN=1`（回到 v79/v79b 老口径，
      
    两条路一起关）。
- **`←` / `→` 也会收起列表**：和"鼠标点到别处"同义——光标移出正在拼的那个词，

### v107c：补完括号后自动弹出形参信息（形参签名）

**用户口径（原话）**："提示词选中了过程名或函数名，按 tab 键，当自动补充完双括号后，
光标落在双括号中间，再加个自动显示形参列表参数的功能。"

按 Tab 确认一个 **Function**（或语言自带的函数，如 `MsgBox`）之后，我们会补一对 `()`、
把光标送进括号中间，**紧接着替用户按一下 `Ctrl+Shift+I`** —— 那是 VBE 自带的
「参数信息 / 快速信息」（`PopupTipWndClass`），弹出来的是**形参签名**
（`GetName(customer As String, index As Long)` 这种）。光标停在哪个参数上它就高亮哪个，
接着打逗号它会跟着往下走，按 `Esc` 收起。

- **为什么调 VBE 自己的、而不是我们画一个窗**：形参信息本来就是 VBE 内置的能力 ——
  它跟着你的输入实时更新（当前参数高亮 / 逗号推进 / 签名改了也跟着变）。
  我们手上只有 `CodeModule` 的**纯文本**，重画一遍做不到这个程度。
  ⚠️ 这与 v103b 撤掉的那件事**不是一回事**：那次是在候选框的"详情行"里塞形参表，
  用户明确说不要（"提示自定义函数的时候，不需要在提示词框最下方提示形参列表"）。
- **只在【我们自己补了括号】的那条路上按**（`added_parens`）：括号本来就是用户敲出来的
  情况，VBE 在他敲 `(` 的当下就弹过了，我们再补一下只会让它闪一下。
  `want_parens=False` 的那些档（`Sub` 补空格 / `Property` 什么都不补 / 变量常量）自然也不弹。
- **失败一律静默**：拿不到注入函数（离线、旧式构造）或 `SendInput` 没命中，
  结果只是"形参信息没弹出来"，**绝不影响补全本身**（同 v103b 注入空格那条规矩）。
- 关掉：`set VBECOMPLETE_NO_PARAM_INFO=1`。

### v108：中文标点不再被"翻译"成英文标点

**用户口径（原话）**："我不能输入中文的双括号和中文双引号，一输入就会自动变成英文的
双括号和英文双引号。"

自动配对的判据过去只看**虚拟键 + Shift**。而中文输入法在「中文标点 / 全角」状态下，
`Shift+9` 敲出来的是全角 `（`、`Shift+'` 是全角 `“`；我们却一律替它插半角 `()` / `""`
—— 等于**把用户的中文标点翻译成了英文标点**。看上去像"输入法坏了"，其实是我们干的。

现在接管按键**之前先问一次输入法的「转换模式」**，中文标点时补的就是中文那一对：

| 你敲的 | 英文标点（半角） | 中文标点 / 全角 |
| --- | --- | --- |
| `Shift+9` | `()`，光标在中间 | `（）`，光标在中间 |
| `Shift+0`（右边已有） | 跨过去，不重复插 | 跨过去，不重复插 |
| `Shift+'` | `""`，光标在中间 | `“”`，光标在中间 |
| `Shift+'`（在未闭合的串里） | 只补收尾的 `"` | 只补收尾的 `”` |
| 退格（光标夹在空括号中间） | 两端一起删 | 两端一起删 |

- **怎么问的**：`ImmGetDefaultIMEWnd(焦点窗口)` 拿到该窗口的输入法窗口，再
  `SendMessage(WM_IME_CONTROL, IMC_GETCONVERSIONMODE)` 问它的转换模式。
  ⚠️ 更直接的 `ImmGetContext(hwnd)` **跨进程拿不到**（实测对别的进程的窗口一律返回 `NULL`），
  所以只能走这条"把 IME 窗口当普通窗口发消息"的路 —— 这也正是官方给的跨进程做法。
  ⚠️ 发消息用的是 `SendMessageTimeout` + `SMTO_ABORTIFHUNG`：这段代码跑在**键盘钩子线程**里，
  目标窗口若卡死必须立刻放弃 —— 低层键盘钩子回调超时会被系统**悄悄摘掉**。
- **判据**：必须**同时**满足「中文模式」(`IME_CMODE_NATIVE` 0x0001) 与
  「中文标点」(`IME_CMODE_SYMBOL` 0x0400) 或「全角」(`IME_CMODE_FULLSHAPE` 0x0008)。
  只要中文模式不亮（英文模式）就按半角 —— 那种情况下输入法自己出的是半角标点。
  常量取自本机 Windows SDK 的 `imm.h` / `ime_cmodes.h`；`0x0400 = 中文标点` 这一条是
  **实测确认**的（探针 `tests/probe_ime_mode.py`：微软拼音「中文 + 中文标点」读到
  `0x0401` = `NATIVE | SYMBOL`）。
- **只在决定接管之后才问**：`Shift` 一按就问的话，每按一次都要发个窗口消息。
- **问不到就是半角**（没有输入法 / API 失败 / 超时）：拿不准一律退回既有行为，
  绝不因为探测失败把功能弄坏。
- **注释里不配对的老规矩不变**：注释里敲 `（` 一律原样交给输入法，
  也就是说中文注释里的全角括号**从来**都是正常的。
- 强制按半角处理：`set VBECOMPLETE_NO_IME_PUNCT=1`。

### v109：开着本工具时，PyCharm / VSCode 又能正常关掉了（老毛病复发）

**用户口径（原话）**："以前改掉了，但是现在又犯了。就是打开这个项目以后，pycharm 里的
项目不能关闭，我俩冲突了。"

同一个坑 v27~v29 修过：**全局键盘/鼠标钩子绝不能在 VBE 之外常驻**。这次的复发点不在
挂载策略，而在一次**看似无害的系统调用**上：

| 环节 | 出了什么事 |
| --- | --- |
| `in_vbe_code_pane()` 读前台窗口标题 | 用的是 `GetWindowText`，而它是**跨线程同步调用** |
| 你关 PyCharm 的那一刻 | 它的主线程在拆窗口、写设置，好几秒不理会消息 |
| 于是 | 我们**自己的主线程**被这一行堵住 **1.5 秒以上**（实测 1.484s；窗口彻底卡死时更久） |
| 主线程一堵 | `reconcile`（每 300ms 一轮、负责"离开 VBE 就卸载钩子"的唯一循环）跑不了 |
| 结果 | `WH_KEYBOARD_LL` / `WH_MOUSE_LL` 继续挂在人家退出流程上 ⇒ **PyCharm 关不掉** |

另外还补了一个**更隐蔽的雷**：`reconcile` 原先只有开头一行有 `try/except`，中后段
（`completer.is_visible()` / `popup.is_busy()` / `backend.release()` …）全是裸调用 ——
任何一处抛异常，这个 300ms 循环就**永久停摆**，钩子永远卸不掉（比"晚 600ms 卸载"
严重得多，只能重启工具）。

现在的两层修法：

1. **读标题之前，先问"这个窗口还响应吗"**（`foreground_window_closing`，`WM_NULL` +
   `SendMessageTimeout`，200ms 封顶）。不响应就直接判"不是 VBE"，**压根不碰
   `GetWindowText`**。v28 的 closing 判据本来就是"无响应就不挂钩"这个口径，这次只是
   把它从"决定挂不挂"挪到了"读标题之前"，顺带把阻塞消掉。实测同样场景下：
   主线程单次耗时 **1.484s → 0.000s**，焦点离开后钩子卸载 **5s+ → 0.26s**。
2. **`reconcile` 拆成"外壳 + 单轮"**：外壳只做两件事 —— 用 `_safe_tick()` 跑一轮
   （这一轮里任何异常都被吃掉），然后**无条件**排下一次。单轮实现叫 `_reconcile_once`，
   里面不再自己 `root.after`。

> 顺带说明：`foreground_window_closing()` 现在可以收一个 `hwnd` 参数 —— 调用方
> （`in_vbe_code_pane` / `reconcile`）手里往往已经拿到了前台句柄，传进来就省得再
> `GetForegroundWindow` 一次；不传时行为与从前完全一致。

复现与验证手段（随仓库发布）：`tests/probe_hook_gate.py` —— 跑**真实的**
`main.py` + **真实的** pynput 钩子，用假窗口真实切换前台，其中一个假窗口可以进入
"wndproc 里睡 N 秒"的卡死模式。它同时给出了两个关键数据：
`SendMessageTimeout(200ms)` 对**同线程**窗口会**等满**对方处理完才返回（超时形同虚设），
而 `GetWindowText` 对**忙着的别的线程**的窗口会堵 1.5 秒以上 —— 后者才是本 bug 的根因。

### v110：Ctrl+↑ / Ctrl+↓ 一键跳到过程的「声明区」/「收尾区」空白行

**用户口径（原话）**："当我按 ctrl+↑，光标会自动定位到当前过程中最后一个 dim
关键字行，如果此行的下一行不是空行，就自动在此行下方新增一行，光标移动到下方空白行；
如果此行的下一行是空白行，就不用新增行，光标移动到下方空白行就可以了。当我按
ctrl+↓，光标会自动定位到当前过程中的 end sub 或 end function 行，如果此行的上一行
不是空白行，就自动在此行上方新增一行，光标移动到上方空白行；如果此行的上一行是
空白行，就不用新增行，光标移动到上方空白行就可以了。"

也就是写过程时的两个高频落点，各用一个快捷键直达：

| 按键 | 落点 | 那一行还不是空白时 |
| --- | --- | --- |
| `Ctrl+↑` | 当前过程**最后一个 `Dim` 语句下面那一行** | 照 `Dim` 行的缩进补一个空白行，光标落上去 |
| `Ctrl+↓` | `End Sub` / `End Function` / `End Property` **上面那一行** | 照收尾行的缩进补一个空白行，光标落上去 |

于是"声明一批变量 → 写代码 → 回头再加一个变量"和"写完想留个空行再收尾"都各一键直达。
（`End Property` 也一并收 —— 用户只提了 Sub/Function，属性过程是同一副骨架。）

**★v110b：Ctrl+↓ 落点是顶格 / 真空行时，再替用户按一下 Tab。**
用户口径（原话）："还有个地方需要修改，ctrl+↓ 跳到结尾空行，能不能再加个 tab 补位？"
—— 收尾行（`End Sub`）惯例顶格，我们照它缩进补出来的新行就是真空行，光标落在行首，
接着写过程体代码还得自己按一次 Tab。现在让 **VBE 自己的 Tab**（带 smart indent）把光标
推到过程体该在的层级：Tab 宽度、用空格还是制表符、缩进几级，全都跟着用户的 VBE 选项走。
⚠️ 只在落点**顶格 / 真空**时补 —— 带着任何缩进的空白行（一级的、不足一级的）说明用户
自己摆过层级，一律不加深；`End` 行自己有缩进（罕见）时插进去就带着缩进，也不补。
⚠️ 顺序是"光标就位**之后**"（与 v107c 注入 Ctrl+Shift+I 同一条规矩）；注入失败 /
拿不到注入函数一律静默跳过，绝不影响跳转本身。想关掉：`set VBECOMPLETE_NO_CTRL_NAV_TAB=1`。

几个值得记下来的设计点：

- **钩子线程一次 COM 都不碰**。"当前过程最后一个 Dim"要读**整个模块文本**，
  而轮询快照 `state["cur_ctx"]` 只有光标所在那一行 —— 为它在钩子里现读模块，
  等于把 COM 搬进键盘钩子线程（v56 的老坑）。所以钩子只回答"这一下该不该接手"
  （模块级纯函数 `_ctrl_nav_vk_ok` 判修饰键，再叠三道运行期闸：输入法组字中
  `pending_keys>0`、COM 退避中、焦点不在代码窗格），判据与写入全在主线程
  `ctrl_nav_jump` 里拿**此刻真读到的**模块文本重算 —— 同一份纯函数实现
  （`vbe_bridge.ctrl_nav_jump_plan`），v87 的规矩。
- **接管不了就把按键原样还给系统**：不在过程里（模块声明区 / 两个过程之间）、
  过程还没有收尾行（正在写的新过程）、本过程一个 `Dim` 都没有、模块只读取不进来、
  锚点复核不过 —— 一律 `send_vk(..., ctrl=True)` 把 `Ctrl+↑/↓` 还回去
  （修饰键**反序**松开）。VBE 原生 `Ctrl+↑/↓` 在代码窗里什么都不做，所以还回去
  也只是"什么都不会发生"，绝不会"吞了按键却没反应"，也不会和原生行为打架。
- **两份行表（masked / raw）**：正则吃抹白后的行（字符串、注释里的 `Dim` 不算声明），
  续行判据吃原始行。为什么必须分两份：`_mask_strings_and_comments` 把整段注释压成
  **一个空格**，`' 注释 _` 行尾那个续行符 `_` 跟着注释一起被抹掉了 —— 只拿抹白行判
  续行，就认不出"下一行是注释的续行"，会把注释里那行 `Dim x` 当真声明，跳过去之后
  还会在注释中间插一行、把注释从中间拆断。续行后半截（上一物理行以 ` _` 结尾）
  在过程头 / 过程尾 / `Dim` 三类判据里一律先排掉。
- **光标就在过程头 / 收尾行上**也算在过程里：刚敲完 `Sub Foo()` 按 `Ctrl+↑` 就该能
  跳进它的声明区；"光标停在 `End Sub` 上按 `Ctrl+↓`"也是最常用的姿势之一。这两个
  口径与 `parser.is_proc_header_line` 问的问题不同（那边问"当前作用域"、这边问
  "归属"），不能套同一句结论。
- **列交给 VBE 自己夹**（`_caret_to_line_end` 给一个远超行尾的列）；新插入的缩进
  可能被 VBE trim 成真空行，所以落光标之前要**重新读一遍**目标行。假编辑器不夹列
  时才退 `_eol_caret_col` 兜底。
- **锚点复核（v21 老规矩）**：写之前再确认一次"目标行是不是空白"必须与计划一致
  （计划说不插就该是空白、说要插就不该是）。不一致说明行号换算错了 —— 宁可这一次
  不跳，也绝不能把空白行插到用户代码中间。写只有一次（`InsertLines`），绝不在
  finally 里补写。
- **分支刻意排在 `completer.is_visible()` 之前**：候选窗开着时，↑/↓ 那条分支不分辨
  修饰键，晚一步就被列表抢走（与 v90b 的 Tab 同一条理）。`Win+↑` 是系统的窗口
  最大化快捷键，修饰键门槛里**绝不**漏掉 Win 键。
- 想关掉（`Ctrl+↑/↓` 完全还给 VBE）：`set VBECOMPLETE_NO_CTRL_NAV=1`。
  只不想要 Tab 补位（跳转保留）：`set VBECOMPLETE_NO_CTRL_NAV_TAB=1`。

## 与 IntelliJ IDEA 的对照

这个项目的目标就是**把 IDEA 那套"聪明补全"搬进 VBE**。VBE 原生只对 `对象.成员`
  
弹列表，对自定变量名 / 过程名一律不管；下面逐条对照 IDEA 的相关能力，说明哪些
  
已经做到、哪些刻意不做、以及为什么。

### 一、已实现（对标 IDEA 的哪一项）

| IDEA 的能力                       | 本项目的对应实现                                                                             | 版本             |
| ------------------------------ | ------------------------------------------------------------------------------------ | -------------- |
| 输入即弹、实时过滤                      | 输入字母/数字/`_` 即弹候选，继续输入实时过滤                                                            | v1             |
| 模糊 / 驼峰匹配（CamelHumps）          | 不要求从首字母起；按「精确 > 前缀 > 词首缩略 > 连续块 > 分散」分级，命中字符标红                                       | v55+           |
| 匹配质量排序                         | 同级再比首个命中位置、跨度、名字长度                                                                   | v55+           |
| **作用域就近优先**（local scope first） | 本过程局部/形参 > 本模块模块级 > 其它模块 Public，作为同分决胜项                                              | **v103**       |
| **最近使用优先**（recently used）      | `Tab` 确认过的名字下次同分时排前                                                                  | **v103**       |
| **关键字后自动补空格**                  | 补全 `pub` → `public `（62 个关键字，排除法）                                                    | **v103b**      |
| **Sub 补空格 / Function 补括号**     | Sub 是无返回值语句 → `DoWork `；Function → `GetName()`；Property 都不补                          | **v103c**      |
| **函数给自己赋返回值时不补括号**             | 在 `Function MyFunc` 体内写 `MyFunc = ...` → 不补 `()`（那里函数名代表返回值的变量，`MyFunc() = 5` 是语法错误） | **v103d**      |
| **声明时不弹候选**（对标 IDEA）          | 在 `Dim …` / `Sub …` / `Function …` / `Property …` / `Const …` / `Type …` 这些**起新名字**的位置一律不弹；`As` 之后的**类型名**位置照常提示 | **v105**       |
| 自动配对括号 / 引号                    | 打 `(` `[` `"` 自动补右半边，光标居中                                                            | v84+           |
| 退格删除成对符号                       | 光标在空括号/空引号中间时一下删两端                                                                   | v99            |
| 智能缩进 / 自动补收尾                   | 回车时注释对齐、块头深一级、`Else`/`Case` 拉正、块头补 `End xxx`                                         | v79~v86        |
| `Shift+Enter` 起新行              | 与回车同源的缩进判定，且列位置任意                                                                    | v88/v89        |
| 补全过程名自动补括号                     | 调用点 `DoWo` → `DoWork()`，光标进括号                                                        | v98            |
| 让位给原生成员列表                      | **`对象.` 之后我们根本不出候选**（v103c 起默认关），整个让给 VBE 的「自动列出成员」                                  | v97+/**v103c** |

### 二、刻意不做，及为什么

IDEA 的这些能力**都建立在一个前提上：IDE 手里有整个工程的、实时更新的语义模型**
  
（类型推断、符号表、依赖图）。VBE 能拿到的只有 `CodeModule` 的**纯文本**（连
  
`Attribute` 隐藏行都读不到）加上我们主动去读的类型库。下面这些要么依赖上面那个
  
前提、要么要在"文本世界"里重造一套编译器前端，**成本与稳定性不成比例**，所以不做：

| IDEA 的能力                           | 为什么不搬                                                                                                                                                                                    |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 跳转定义（`Ctrl+B`）/ 查找引用（Find Usages）  | 需要精确的符号表与作用域解析（同名遮蔽、类成员、`With` 块…）。VBE 不给光标下的符号信息，自己在文本上做一套必然误判。                                                                                                                         |
| 重命名重构（Rename）                      | 同上，且要改多个模块的文本、还要保证不漏改/不多改——在无符号模型时风险太高。                                                                                                                                                  |
| 实时语法检查 / 错误高亮                      | 需要一个持续解析的后台与 VBA 语法子集，误报会直接干扰写作。VBE 自己编译时会给错误，交给它。                                                                                                                                       |
| 后缀补全（`.var` / `.if` / `.not`…）     | 依赖类型推断决定"能套哪个模板"。                                                                                                                                                                        |
| Postfix / 语句补全、Live Template       | 同上；且模板体系是另一套交互，与"补名字"目标无关。                                                                                                                                                               |
| 类型感知的成员补全（本工程对象）                   | VBE **原生就有**（`.成员` 弹窗），而且按真实类型解析、比我们准。v98 试过"按声明类型把候选收窄"，只覆盖得了一部分（本工程类模块 + `Dim x As 类型`），宿主对象 / UDT / `With` 块收不了就退回裸名池 ⇒ **★v103c 起干脆不出这一处的候选**（默认关，`VBECOMPLETE_MEMBER_POPUP=1` 可恢复）。 |
| 代码格式化 / 快速修复                       | 与"补全"正交，且会改写用户代码，风险大于收益。                                                                                                                                                                 |
| 补全列表里显示**形参表**（`foo(int, String)`） | **试过，又去掉了**（v103 → v103b）。VBE 的候选窗本来就窄，在它最下方再挂一行形参在窄窗口里很占地方、反而干扰视线。用户原话："提示自定义函数的时候，不需要在提示词框最下方提示形参列表。"（形参提示交给 VBE **原生的参数信息气泡**，那个是按需触发的、不占地。）                                          |

一句话：**我们复刻的是 IDEA 补全的"体感"（输入即弹、模糊命中、最近用的优先排前、
  
补关键字带空格、Sub 补空格 / Function 补括号），不是 IDE 的整个语义基础设施。**

### 三、口径与 IDEA 不同之处（有意为之）

- **候选池默认含 VBA 关键字与内建函数**：IDEA 只提示作用域内符号；这里为了照顾
    
  "VBE 里连关键字都打不顺"的场景，把关键字 + 内建函数（约 260 个）也收进池子，
    
  但**枚举一律不收**（用户口径："枚举加上就太多了"）。可用环境变量按需关掉。
- **"语言自带"永远排在你自己的名字后面**：`decl` 同时命中 `Declare`(关键字) 与
    
  `declaredVar`(你的变量) 时，后者优先 —— IDEA 里关键字通常不参与补全，没这个问题。
- **不做隐式变量的类型推断**：无 `Option Explicit` 时"用过即存在"的变量也提示，
    
  但按**首次出现的过程**归属作用域，不去猜类型。

### 跑回归测试

双击 `run_tests.bat`，或：

```
python tests\test_real_project.py
```

- **不需要 Office / COM**，用 `tests/testdata/` 里那份真实工程导出的 14 个模块
    
  作样本，纯解析层验证。
- 有几条用例会真读【当前宿主】的类型库、并断言 Excel 专属常量名；宿主不是 Excel
    
  （如 Word / PPT / WPS）时会**自动跳过**；一个宿主都没开时才红（少量、预期内，见下）。
- ⚠️ **必须用装了 `pywin32` 的 Python 跑**。一个宿主都没开时，Excel 专属那几条会红：
    
  那属预期（**不是代码坏了**）；换成开着 Word / PPT / WPS 的机器再跑，它们会自动跳过。
- **改了代码请跑一遍。** 这个项目绝大多数坑（列语义、作用域口径、候选排序）
    
  都是"看起来对、真机或离线用例一跑就红"才发现的。

⚠️ **`log.py` 不能删**：`engine.py` / `vbe_bridge.py` / `main.py` 都
  
`import` 它，删掉会直接 ImportError 起不来。留着它而不是把那约 60 处
  
`_log(...)` 调用逐个挖掉，是因为 `log()` 第一行就 `return` ⇒ 主循环里
  
`if _LOG_ENABLED:` 包着的诊断块（含额外的只读 COM 调用）自动整段跳过，
  
**行为与开销都与删掉一样**。

**★v101 起这个后门是真能用的**（原先恒为 `False`，等于把排障设施彻底封死，
  
`Call` 那个故障查了两轮查不动，根因之一就是它）：启动前设 `set VBECOMPLETE_LOG=1`，
  
日志会写到项目目录下的 `VbeComplete.log`（可用 `VBECOMPLETE_LOG_FILE` 换路径），
  
关掉时仍是零开销（实测 10 万次调用 0.024 秒，那都是函数调用本身的开销）。
  
**下次再遇到"某处不生效"先开它**——日志里有一行
  
`accept: ... want_parens=... | in_proc=... is_func=... is_type=...`
  
把括号决策的**每一项输入**真值都打出来了，不用再靠猜。
  
⚠️ **加日志要加在"判据的输入"那一层**，不能只加一行"某某失败了"——
  
只打 `want_parens=False` 等于没有新信息。

其余文件一行不动。配套的 `run_debug.bat` / `show_log.bat` 已随收尾移除，
